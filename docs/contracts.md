# Contracts and execution semantics

Suite JSON is version 1.0, checked against `schemas/suite-v1.schema.json` and semantic validation before execution. Unknown properties and types fail. Stable unique test IDs are mandatory; explicit source/target column mappings and at least one composite key component are required. `dataComparison` and `sqlAssertion` are the supported registry IDs. SQL assertions select exactly one rowCount or typed scalar expectation. Scalars must return exactly one row and one column. SQL result columns require distinct names.

Parameter declarations support string, int64, decimal, boolean, datetime, datetimeoffset and guid. Precedence is repeated CLI override (last occurrence), then declaration default; missing required values fail before execution. Decimal values use invariant dot syntax. Datetime values use `yyyy-MM-ddTHH:mm:ss[.fffffff]` without an offset; datetimeoffset values use round-trip ISO format. Parameters are SqlParameter values, never SQL interpolation. Optional omitted parameters are not bound; SQL referencing them will report an execution error. Supply a default for every referenced optional parameter.

CLI suite, environment and output arguments are explicitly relative to the current working directory, then normalized to absolute paths. Suite JSON contains no other file references in v1. Desktop data resides in `%LOCALAPPDATA%/EtlTestStudio` (suite copies, history JSON, work index and report directories). Working data paths are injectable through RunOptions. History uses one atomically saved portable JSON file per run, rather than a shared SQLite history database. At most 200 recent history artifacts are loaded; retention cleanup is manual in v0.1.

## Exact comparisons

Both sides stream into an ephemeral SQLite index with a 4 MiB page cache and batches of 1,000 inserts. Grouping and ordered scanning happen on disk; a DataTable is never used. This strategy is also used for same-database pairs in v0.1. Server-side optimization is deferred. A single very large row or LOB can still require proportional memory. Evidence is capped independently at 0–10,000 examples per test; all rows are validated. UI evidence pages contain at most 200 retained examples. Work files are deleted after completion/cancellation; a process crash may leave a work index for manual cleanup. These files and evidence contain data: use a suitably protected local/CI directory.

SQL metadata validates schema/table/column names, then identifiers are bracket-escaped. Column spelling uses exact metadata case, even on case-insensitive databases. Data keys use typed, length-safe JSON tuples and binary/ordinal equality independent of SQL collation; string keys are case-sensitive and preserve whitespace. Integral and decimal SQL numbers share the decimal kind and normalized invariant representation. Differently typed keys do not match. Composite keys cannot collide through separator characters. Key normalization is fixed in v1. A null component rejects the group; null-key row counts include both sides. Duplicate groups on either side are reported once per business key and entirely excluded from matching; their representative payload is never compared. A null-key group is classified as null-key rather than additionally as duplicate.

Null equals null; null differs from an empty string unless emptyAsNull is explicit. Trim happens before empty normalization and ordinal case comparison. Decimal tolerance is absolute and inclusive. Floating-point values use exact round-trip representations; decimal tolerances do not apply to float. Datetimes compare wall-clock ticks, optionally within an inclusive millisecond tolerance. SQL datetime never acquires an implicit UTC timezone. Datetimeoffset normalizes to the same instant in UTC. Incompatible mapped value types report execution error. Unsupported SQL values also report error rather than a silent string conversion.

MismatchedRecords counts matched business keys with any differing field. FieldMismatches counts differing columns. Missing/extra rows, duplicate key groups, null-key rows and assertion failures have separate counts. Violations counts stored-evidence events before sampling: one per differing field, missing key, extra key, duplicate group, null-key group or failed assertion. EvidenceTruncated compares that count with retained examples. No suite-wide unique record total is inferred.

Sequential, bounded concurrency (one check at a time) ensures stable test ordering. Indexed keys use stable binary order. Reads are separate read-committed statements, including across connections; **no shared transaction/snapshot is claimed**. Run against a quiescent source/target boundary. No NOLOCK, EXCEPT-based duplicate loss, hash-only equality or silent sampling is used.

## Results and reports

All reporters consume the canonical RunResult with run identity, normalized suite hash, environment, UTC timestamps, scope, strategy, demo flag, typed evidence and per-test outcomes. Secrets and connection strings are excluded. Logs redact database exceptions to SQL error numbers/actionable connection guidance or exception types. Intended data evidence may itself contain sensitive business values; distribute it according to your team's data policy.

Run statuses include Passed, Failed, Error, Skipped and Cancelled; live progress also emits Running. Error checks have partial diagnostic counts. Cancelled runs remain incomplete and preserve earlier outcomes. Run-level cancellation wins over execution error, which wins over required validation failure. Disabled and selection-skipped checks are distinct from passed checks; partial scope is labeled. No baseline or checkpoint exists, so no selection advances one. Bound business scope parameters are stored as typed runtime parameters for reproducibility; credential secrets must be connection environment references, never suite runtime parameters.

HTML is escaped and standalone with inline styles; details expand without JavaScript. CSV quotes every value and prefixes spreadsheet-formula text. JSON preserves types. JUnit uses failure for required assertion failures, error for runtime failures, skipped for cancelled/skipped tests and system-out for warning failures. Report-generation failure returns exit 2; already written diagnostic files are preserved. JSON can re-render reports using the reporting library; a dedicated render command is deferred.
